# OpenTree · 树上的朋友 🎄

种一棵圣诞树，回答十个关于自己的小问题，把链接发给朋友。看看谁最懂你，也把朋友的留言挂上树。

**没有广告、追踪、注册、付费依赖或第三方 CDN。** 原生 HTML / CSS / JavaScript，MIT 开源，直接部署到 GitHub Pages。

[打开网站](https://xhc144.github.io/open-friend-tree/) · [复制这个模板](https://github.com/new?template_name=open-friend-tree&template_owner=xhc144) · [部署步骤](#复制一份自己的站点)

## 可以做什么

- 自己起昵称、挑头像，编辑5–10道问题及选项，选择自己的答案。
- 生成独立的邀请链接，无需朋友登录；朋友每题二选一，完成后按得分爬树。
- 看答案回顾、写留言、生成成绩回执；树主导入后，朋友出现在树与排行榜里。
- 分享带有最新成绩快照的树链接；导出 JSON 备份，在其他设备上恢复。
- 桌面与手机布局，原创 SVG 圣诞树，本地保存自己的树。

## 纯静态版的成绩如何汇总

GitHub Pages 只发布静态文件，不提供数据库。这个版本**不声称有自动同步的公共排行榜**：

1. 树主创建问答，把「邀请链接」发给朋友。
2. 朋友答完，点「复制成绩回执」，把完整链接发回树主。
3. 树主打开回执链接（用创建树的浏览器），或在自己的树里粘贴导入。
4. 成绩与留言存进树主浏览器。重新复制邀请链接，便会带上当前榜单快照。

旧链接中的榜单不会自动变化；其他人不会自动看到后来导入的成绩。同一个朋友可以重新答题，每次作答是独立记录；重复导入同一份回执不会重复计分。

这使整个站点可以独立运行，不依赖站长的服务器、API 密钥或某个免费云数据库的额度。若你要免回传的实时公共榜，需要另加服务端存储，属于此静态版以外的功能。

## 复制一份自己的站点

1. 点击仓库上方 **Use this template → Create a new repository**（或 Fork）。选自己的账号，仓库设为 **Public**。
2. 进入新仓库 **Settings → Pages**。
3. 在 **Build and deployment** 中，Source 选择 **Deploy from a branch**，Branch 选择 **main**，目录选择 **/ (root)**，点 **Save**。
4. 等待 GitHub 完成发布。在同一页面点 **Visit site**；网址通常为 `https://你的用户名.github.io/你的仓库名/`。

无需安装 Node.js、申请 API、配置密码或执行构建。项目全部使用相对路径，仓库改名也能运行。`index.html` 是入口，`.nojekyll` 告诉 Pages 直接发布这些文件。

GitHub 官方说明：[创建 Pages 网站](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)。如果第一次部署没有立刻打开，查看仓库 **Actions** 中的 `pages build and deployment`，等待成功后再刷新。

## 本地运行与修改

```bash
git clone https://github.com/xhc144/open-friend-tree.git
cd open-friend-tree
python -m http.server 8080
```

打开 `http://localhost:8080`。本项目使用 ES Modules，请通过 HTTP 打开，避免直接双击 HTML 产生模块访问限制。

| 文件         | 用途                                       |
| ------------ | ------------------------------------------ |
| `index.html` | 页面入口、元信息                           |
| `styles.css` | 原创界面、响应式布局与动效                 |
| `app.js`     | 创建、答题、树、成绩回传和备份界面         |
| `lib.js`     | 数据验证、链接编解码、评分、回执与本机存储 |
| `assets/`    | 原创静态资源                               |
| `tests/`     | 核心逻辑与浏览器验收脚本                   |

默认问题在 `lib.js` 的 `DEFAULT_QUESTIONS` 中，可直接编辑。改站名、颜色与文案，主要编辑前三个文件。没有构建产物和源文件不一致的问题。

## 数据与使用边界

开发者可以运行 `npm test`（需要 Node.js，无需安装 npm 依赖）。真实浏览器验收脚本为 `tests/browser_qa.py`：安装 Python 的 `playwright` 包及其 Chromium 后，在本地服务启动的情况下运行 `python tests/browser_qa.py --url http://localhost:8080/`。测试使用虚构昵称及隔离浏览器，不会写入公共数据库。

- 树和题目答案通过 URL 的 `#` 片段传给朋友；可读取链接的人可以检查题目与正确答案。适合好友小游戏，**不是防作弊考试系统**。
- 回执会重新计算得分、验证所属树及题目版本、去重；没有服务器签名，不能证明作答人身份或防止主动伪造。
- 本机数据只在当前域名、当前浏览器保存。换设备、无痕窗口、清理网站数据或换仓库域名后，需要导入备份才能恢复自己的树。
- 请不要把密码、联系方式、隐私问答等放进分享链接。收到回执后先确认朋友同意把昵称与留言收录到分享的榜单。
- 分享链接相对较长；某些聊天应用可能截断。请使用完整复制功能，必要时换浏览器打开完整链接。
- 现代浏览器通过 CompressionStream 压缩链接；不支持压缩的创建端会输出普通编码，读取压缩链接需要支持 DecompressionStream 的较新浏览器。
